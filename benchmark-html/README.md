# Benchmark HTML — Interactive LLama-Bench Visualization

## Purpose

A single-file web app for loading, filtering, and visualizing llama-bench results from the `data/` directory tree. Pure token speed tests (tgs = tokens per second, pp = prompt processing). Not measuring quality of tokens.

## Data Source

- Generated by `./benchmark` script (docker-compose runner)
- JSON files live in `data/<YYYY-MM-DD-HHMM>/<service>-benchmark.json`
- Each JSON file = array of benchmark runs, one per prompt/gen config
- Each run has: `model_type`, `backends`, `n_prompt`, `n_gen`, `avg_ts`, `stddev_ts`, `samples_ts`
- Filenames encode model/backend info (e.g. `qwen36-35B-A3B-rocm-6.4.4-benchmark.json`)

## Architecture

### Single HTML file, no build step

Everything lives in `benchmark.html`. Vanilla JavaScript, no framework, no transpiler.

### Data loading — hybrid mode

1. **HTTP mode** (primary): Tries `fetch('/data/')` to discover JSON files from a directory listing. Works when served via `python3 -m http.server` or any static server. No user interaction needed.
2. **Picker mode** (fallback): Falls back to `showDirectoryPicker()` File System Access API. User selects the `data/` folder once per session. No browser flags needed for basic use, but Firefox requires `dom.filesystem.enabled` flag.

On reload: HTTP mode works automatically. Picker mode requires re-selecting the directory (browser limitation — handles don't persist across reloads).

While the page stays open, both modes poll for new files (HTTP: re-fetch listing; Picker: call `directoryHandle.values()`).

### Charting library

**Plotly.js** — chosen for multi-chart-type support without rewriting data pipelines.

Supported chart types:
- **Line chart** — primary view. tgs vs prompt length (512/1024/2048). Each line = one backend/config.
- **Radar chart** — compare models across multiple metrics (tgs at each prompt length, stddev, etc.)
- **Scatter plot** — tgs vs model size for quantization comparisons
- **Box plot** — distribution of samples across runs

### Export

- **PNG** — `Plotly.toImage(chartDiv, 'png')` for quick sharing
- **SVG** — `Plotly.toImage(chartDiv, 'svg')` for embedding in docs
- **TSV** — export filtered data table as TSV (tab-separated)
- **Generate `benchmarks.md`** — one-click button that renders all selected charts as SVG and produces markdown text to paste into the repo. Enables a static "snapshot" of comparisons for GitHub Pages or TiddlyWiki.

### Interactivity

- **Filters** — dropdowns/sliders for:
  - `backends` (ROCm, Vulkan, etc.)
  - `model_type` (model family)
  - quantization (parsed from `model_type`, e.g. Q8_0, Q6_K, BF16)
  - ROCm version / Vulkan driver (parsed from filename or `backends` field)
  - date range (from directory name)
- **Multi-select** — select multiple items to compare on one chart
- **Chart type toggle** — switch between line/bar/scatter/radar/box without data pipeline changes
- **Hover tooltips** — show full run metadata on hover
- **Lasso selection** — select data points directly on chart

### Comparison use cases

- Compare backends for same model (ROCm 6.4.4 vs 7.2 vs nightlies)
- Compare quantizations for same model (Q8_0 vs Q6_K)
- Compare different models (Qwen3.6 vs Qwen3.5)
- Compare ROCm vs Vulkan for same model
